# Visual Evidence Policy

InstabotAI documentation uses visual assets for three purposes: product orientation, architecture explanation, and release/runtime evidence.

## Product screenshots

Product screenshots must come from a runnable current build. The canonical consumer-console capture is generated by the manual **Docs Visual Capture** GitHub Actions workflow, which installs the package, starts the real FastAPI console, waits for `/healthz`, and captures the Overview with headless Chrome.

The capture workflow is intentionally read-only with respect to repository contents. It uploads a capture candidate containing the PNG and generated provenance metadata. It does not commit or push the image itself. Adopting a new screenshot into the repository requires a reviewed change that updates all three together:

- `docs/screenshots/consumer-console-overview.png`;
- `docs/screenshots/CAPTURE_PROVENANCE.md`;
- the matching inventory/provenance entry in `docs/PRODUCT_SURFACES.md`.

This prevents a newly captured image from inheriting stale provenance from an older source commit or workflow run.

Do not hand-create or edit a product screenshot to imply authenticated provider success, populated campaign state, AI success, or account activity that was not actually observed.

## Architecture diagrams

Maintained SVG diagrams may summarize code architecture and control boundaries. They must match the current canonical implementation and must not be presented as runtime screenshots.

## Authenticated evidence

Authenticated Instagram/model screenshots are intentionally selective. They may be added only when:

1. the run used the current candidate or release;
2. credentials, tokens, account IDs, personal information, and private content are absent or safely redacted;
3. the capture does not expose a secret through browser devtools, URLs, logs, or exception text;
4. the exact candidate/release and capture purpose are recorded in `docs/PRODUCT_SURFACES.md`.

## Maintenance

The Quality Gate verifies local image references in README and top-level docs so missing or empty repository assets fail CI. `docs/screenshots/README.md` catalogs the currently maintained visual set.

A screenshot refresh is incomplete until its image, capture provenance, and product-surface inventory all identify the same evidence source.
